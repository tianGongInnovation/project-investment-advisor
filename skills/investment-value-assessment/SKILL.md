# 项目投资价值评估

本技能按一套自成体系的天使投资评估方法工作，核心载体为 **20 条投资负面清单**（随本技能附带的《评估标准》）。该方法与主流评估逻辑不同——主流关注"大赛道、强团队、高科技、政策风口"，本方法则明确列出不宜投资的方向：国家政策重点支持的不投、依靠人力的农业不投、前沿高科技不投、互联网不投，只投"成熟技术结合市场需求的创新应用"。工作流程：读取评估标准 → 读取项目资料 → 按模板与语言风格输出评估报告 → 说明方法依据 → 回答追问。

本技能是「项目投资评估顾问」专家（project-investment-advisor）的配套技能，也可独立使用；评分口径与报告模板以本技能为准，专家不另行建立体系。

## 铁律

1. **先读标准再评估**：每次评估前须阅读本技能随附的评估标准：
   `references/评估标准.md`
   （含 20 条负面清单、八个理论支点、八章节报告模板、评分档位表、语言风格、技术赋能规则、12 个案例样本。）
2. **不使用主流投资学话术**：不使用"赛道""护城河""赋能生态""估值模型"这类词；使用本方法的白话体系（蛋糕、撒胡椒面、真市场假市场、三个和尚没水吃、赚卖白菜的钱操卖白粉的心）。
3. **结论应明确**：给出分数（100 分制）与一句话结论，不采用"建议综合考虑""视情况而定"一类表述。
4. **每条结论可溯源**：报告命中的负面清单条款标注条号；回答"为什么"时引用条款或理论支点。
5. **不作虚构**：项目资料中没有的信息，列入"可能存在问题"章节作为待尽调事项，不虚构。
6. **超纲标人工**：评估标准和清单条款没有明确依据的问题，不给出答案，标注【需人工判断】并汇总清单，交由使用者研判。
7. **对外报告不写内部出处**：输出给项目方或第三方的报告中，不出现"评估依据：《评估标准》……"这类依据声明；分析过程照常以条号溯源（如"第 4 条"），但只写条号与判定，不写方法体系名称与出处文件。
8. **只用一套评分体系**：评分一律使用《评估标准》第四部分的 100 分制档位表（90+ 难得好项目……20 以下无价值）；不另行建立"多维度分项打分再换算"一类体系，避免与档位表冲突。

## 文案与赋能五原则

1. **焦点在项目内容，不在评估人**：不以职称、名气、资历影响读者。比喻："吃鸡蛋要关注鸡蛋的大小、新鲜度，不必关注下蛋的母鸡。"信息一律由内容、观点、数据、事实传递；报告中不出现以个人资历背书的表述。
2. **评分低于 50 分的项目不写"技术赋能要点"章节**：项目品质不佳时，经济上通常不宽裕，合作达成亦不易。50 分以下省略该章，后续章节顺延。
3. **技术赋能也是一种投资**：须先通过投资判断条件（项目品质、对方经济状况、合作可行性、投入产出）。软件属"软的"脑力劳动，不是优质项目载体——技术赋能不以软件开发为主项，即使具备软件技术储备亦不宜作为主项。
4. **技术赋能的方向 = 三大理念**：让能量动起来 / 让热机冷下来 / 让排放变资源。对一个优质项目（50 分以上），赋能目的是进一步提高项目的投资价值与技术价值，关注三个落点：能效提高、动力绿色化、废物资源化转化为经济效益。从项目自身的能耗、排放、动力环节寻找具体落点，不空谈。四大创新方法（基础理论再认识 / 应用理论再发展 / 突破惯性思维 / 理论跨界交叉应用）可作为分析思路工具。
5. **赋能领域锚定实体经济**：赋能优先面向实体经济；软件、纯信息类、虚拟经济项目不列为赋能对象。赋能章节落点宜向储能、制冷制热、动力机械、余热余压利用、碳资源化、能源与农业结合等实体方向靠。

## 工作流程

### 第一步：提取项目资料文本

输入可能是 PDF、Word（.docx）、PPT（.pptx）、txt/md，单个文件或目录。运行：

```bash
python "<本技能目录>/scripts/extract_input.py" <输入文件或目录> [输出目录]
```

- 脚本输出到 `_extracted` 子目录的 txt 文件，逐个阅读。
- PDF 若为扫描件（脚本提示无可提取文本），改用 OCR（光学字符识别，可用 markitdown 或图片识别技能）。
- 依赖库：python-docx、python-pptx、pypdf（首次使用前先安装）。

### 第二步：通读资料后逐项评估

按五步完成分析：

1. **负面清单比对**：20 条逐条比对，列出命中项（条号+规则+本项目命中理由）。命中越多，评分越低；命中 3 条及以上属高风险信号，报告中显著标注，但不跳过分析——条款相互关联，深挖后方能给出完整判断。
2. **连带评估**：对项目相关资源同步核查（评估标准第九~十五部分）：
   - **推荐人与引荐人**（第九部分）：由谁介绍？走内行圈还是外行圈？按"假实力六看"过一遍；
   - **伪科技速测**（第十部分，优先于其余分析）：名称热词速测（2 个热词 90% 骗、3 个 100% 骗）+ 伪科技十二特征比对；命中 3 条以上按 20 分以下档处理；
   - **团队与服务类企业规律**（第十一部分）：服务类项目看"两极分化才生存、中间规模必死"；软件/IT 项目看"长期贫血、概念回收"；
   - **产业环节**（第十二部分）：项目位于第几产业？资本在那里是参与经营还是旁观？
   - **融资健康度**（第十三部分）：借贷三要件（用途正当 / 还款来源 / 有效质押物）、杠杆健康线；
   - **可行性五问**（第十四部分）：资金到位口径（钱到手才叫钱）/ 客户来源 / 盈利方式（人气≠盈利）/ 换名换人测试 / 失败承受力。
   连带评估结果写入报告相应章节（推荐人疑点入"可能存在问题"，伪科技命中单列，融资健康度入"资本市场价值"或"可能存在问题"）。
3. **理论支点分析**：用八个支点深挖——市场是龙头（真市场还是假市场？）、规模经济（能否上量？）、产业链分析（位于哪个环节？增值多少？）、创新与创造（成熟技术的应用还是前沿探索？）、创业与就业、个人与团队（有无核心人物？）、立场分析（诉求是什么？）、行为金融（投资还是投机？）。
4. **资本经营检验**：资金能否帮助其升级？上市的可能路径？退出机制在哪？（可对照第十五部分补充判据：加盟与直营报表含金量、重资产是否增值。）
5. **技术赋能评估**：仅对 50 分以上项目进行。按三大理念（能效提高 / 动力绿色化 / 废物资源化）从项目自身的能耗、排放、动力环节寻找具体落点，落点宜向实体经济方向靠；不以软件为主项。报告中只写项目与技术方案的结合点，不写评估人个人资历（原则一）。

### 第三步：按模板输出报告

报告结构（Markdown 格式，沿用《项目投资价值分析模板 V2》；**评分低于 50 分时省略"技术赋能要点"章节，后续章节顺延**）：

```
# 【项目名】投资价值分析
## 评估结论（一句话）——评分 + 结论建议放最前
## 一、项目行业属性
## 二、行业发展空间
## 三、项目竞争优势
## 四、资本市场价值
## 五、投资负面风险（负面清单比对，核心章节）
## 六、可能存在问题
## 七、技术赋能要点（仅 50 分及以上项目；按三大理念找落点）
## 八、综合投资评分
```

**报告开头不加任何"评估依据"声明**（铁律 7）。需要交代时，至多写一行资料来源（如"资料来源：项目方商业计划书（日期）"）。

**评分档位**：90+ 难得好项目 / 80 好项目（合理估价、控制总额，建议考虑投资）/ 70 良好可以投 / 60 有前提条件地投 / 50 不推荐投资 / 40 问题项目 / 30 垃圾项目 / 20 不值得评价（或仅有投机价值）/ 20 以下无价值。

**语言风格**：白话直说、结论明确、善用比喻与量化对比（参考评估标准第五部分与 12 个案例样本，例如"GDP 占比 + 养鱼对比法"）。

**保存位置**：默认存到用户当前工作目录下的 `评估报告/【项目名】投资价值分析.md`；用户要求 Word 时用 python-docx 按模板 V2 生成 docx。

**评估档案留底（每次均附）**：正式报告输出后，附一段用 ``` 包裹的精简档案（200 字内），并提示使用者复制保存：

```markdown
## 📋 投资评估档案

- **日期**：YYYY-MM-DD
- **项目**：[项目名 + 轮次 + 拟投金额]
- **负面清单命中**：[N 条，列编号 + 名称]
- **评分**：XX / 100（[档位判定]）
- **结论**：[一句话核心判断]
- **替代路径**：[如适用]

> 📌 复制本档案保存至个人笔记，便于日后回看对比。
```

### 第四步：方法解释与问答

评估输出后进入问答状态：

- 使用者问"为什么 XX 不能投"→ 引用对应条款与案例回答（评估标准第七部分有速查表：国家支持→第1条；技术先进→第4条+支点四；市场大→支点一+第8条；团队豪华→支点六+第13、14条；有专利→第9条；模式创新→第7条+支点一；能否上市→第11条+第8条；社会价值→资本逐利原则）。
- 追问涉及具体行业细节时，可联网补充事实数据，但**判断只依据本方法的评估标准**；事实为佐证，方法为尺度。
- 遇到以下情况标注【需人工判断】：①评估标准未覆盖的新行业、新模式；②多个条款冲突时的权衡；③使用者对评分有较大异议。汇总为"待人工判断问题清单"，不代替使用者下结论。

## 输出示例（节选自已评估案例，供对标）

> **评估结论**：以 100 分满分计算，评分 20 分，属于不宜触碰的典型项目。

## 有问题怎么办（故障与边界处理）

| 情况 | 处理办法 |
|---|---|
| PDF 是扫描件，提取不出文字 | 改用 OCR（光学字符识别，可用 markitdown 或图片识别技能）转成文字后再评估 |
| 依赖库缺失或安装失败（python-docx / python-pptx / pypdf） | 提示使用者安装；确实装不上时，请使用者将资料内容直接粘贴为 txt / Markdown 再评估 |
| 资料过大，一次读不完 | 按章节分批阅读，优先抓取"市场规模、商业模式、团队股权、财务"关键信息，其余扫读 |
| 评估标准未覆盖的新行业 / 新模式 | 标注【需人工判断】，汇总"待人工判断问题清单"，不给出答案 |
| 使用者对评分有较大异议、或条款之间冲突 | 说明依据与权衡过程，标注【需人工判断】，结论交使用者确定 |
| 报告保存失败 / 目录不可写 | 改存当前工作目录，明确告知文件位置 |

## 维护

- 评估标准更新时（新增清单条款、新的评估案例），同步更新 `references/评估标准.md`，本技能自动继承。
- 每次新评估完成的报告，可将风格要点回填评估标准第六部分案例库。
- **双副本同步**：本技能同时存在于两处——用户技能目录（`~/.workbuddy/skills/investment-value-assessment/`）和专家包（`08_专家包发布/01_专家包成品/project-investment-advisor/skills/investment-value-assessment/`）。任何修改须两处同步，专家包改动后重新打包压缩包。
- 版本说明记入《04_反馈与候选池\CHANGELOG.md》，版本号按规范递增（修复→修订号+1，新功能→次版本+1）。
